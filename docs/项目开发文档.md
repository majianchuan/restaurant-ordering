# 项目开发文档

**项目名**：Restaurant Ordering / 餐厅点餐系统
**项目概述**：用于在某个餐厅中提供在线点餐服务。

## 开发目标

- 本项目主要用于功能演示和开发测试，不用于生产环境。
- 开发时以“完整实现需求、主要功能正常运行”为首要目标，不以生产环境质量为目标。除非需求中明确要求，否则不需要为了生产环境而额外实现复杂的安全、性能、可扩展性、容灾、监控、日志、自动化测试、CI/CD 等机制。

## 开发过程

- 遇到非关键问题时，应优先采用简单、直接、可靠的实现方式，不要为了追求理论上的完美方案而过度设计。
- 如果存在多种实现方案，在满足本项目需求的前提下，优先选择实现简单、开发成本低、容易验证的方案。
- 除非文档明确要求，否则不要自行扩大项目范围或增加额外功能。
- 不要求为了达到“生产级”标准而继续无限优化。

## 技术要求

- 前后端分离
- 前后端用 HTTP 通信，尽量遵循 RESTful API
- 用 JWT 做用户认证
- 前端为 SPA 项目，技术栈：
  - Vite
  - pnpm
  - React
  - TypeScript
  - Ant Design
  - React Router
  - Axios
  - 其他任何较流行或社区认可的包
- 生产环境下 HTTP api 根路径为 `/api`，开发环境下为 `http://localhost:8000/api`
- 数据库为 MySQL
- 数据库表的设计中，尽量遵循更高级别的数据库范式（1NF、2NF、3NF、BCNF）
- 用户密码在数据库中存储用哈希后的结果，选取恰当安全的适用于密码存储的哈希算法
- 后端为现代 PHP 项目，可以使用任何较流行或社区认可的包
- 后端不使用 Apache 或 Nginx，只用 PHP-FMP 运行
- 后端通过读取明文配置文件 `backend/.env` 连接数据库
- 要有启动脚本，设置 PHP 工作目录为 `backend/`，Web 根目录为 `frontend/dist`，在 `0.0.0.0:8000` 上运行服务

文件结构大致如下：

```text
restaurant-ordering/   # 项目根目录
├── frontend/          # 前端项目目录
│   └── dist/          # 前端项目构建输出目录
├── backend/           # 后端项目目录
├── start.bat          # Windows 系统下项目启动脚本
└── start.sh           # Linux 系统下项目启动脚本
```

## 功能要求

- 共 4 个角色：店长，厨师，收银员，客户
- 客户没有账户不需要登录，其他角色需要登录
- 需要登录的角色的账户不仅有用来登录的用户名，还有用于显示的昵称
- 需要登录的角色都可以修改密码，修改时新密码要输入两遍确保一致，不对密码复杂度和安全性做限制
- 共 5 个主页面：登录页面，店长的管理页面，厨师的后厨页面，收银员的收银页面，客户的点餐页面
- 由于是小店，需要登录的角色可以“永久登录”
- 店长的权限：
  - 创建删除其他角色的账户，创建时需要指定角色、用户名、密码、昵称，昵称输入框内自动填充为可修改的“角色名 + 随机4位编号”，密码输入框内自动填充为可修改的“123456”
  - 增删餐桌的个数，默认名字当前餐桌个数的数字+“桌”，如果已经有同名餐桌则自增数字直到不重名
  - 修改餐桌名字，名字不能重复
  - 显示选定餐桌的点餐二维码，二维码不应该在修改餐桌名后失效
  - 增删改菜单项，每个菜单项有名称、价格、描述、图片、分类。图片是要可以上传的，删除菜单项同步删除图片。
  - 增删改菜单分类，每个菜必须属于一个分类，如果某个分类中还有菜品就不能删除这个分类
- 厨师的权限：
  - 查看所有餐桌的点餐信息
  - 标记某个餐桌的某个菜是否做好
- 收银员的权限：
  - 查看所有餐桌的点餐信息
  - 标记某个点餐订单是否结账
  - 结账时不管是否有菜处于未做状态，认为所有菜都做好了
- 客户的权限：
  - 查看菜单
  - 点餐，每样菜可以增减数量
  - 点提交按钮就可以提交订单
  - 提交点餐订单后可以继续修改点餐结果并提交，新订单覆盖旧订单
  - 可以多个人同时扫一个二维码点餐，相互同步点餐结果，后提交直接覆盖前面人的点餐
- 客户扫描店长展示的某个餐桌二维码后就进入这个餐桌的点餐页面

## 具体页面

### 管理页面

整体类似普通后台管理系统的页面。

### 后厨页面

多列（根据宽度调整列数）卡片布局，每个卡片代表一个餐桌，卡片上显示餐桌名字、点餐状态、已做菜品数量、未做菜品数量，点击卡片可以查看该餐桌点菜的列表，并提供标记某个菜是否做好的功能。有未做菜品时，卡片颜色应该和其他状态的卡片颜色不同。订单结账后已做和未作菜品数量都是0

### 收银页面

多列（根据宽度调整列数）卡片布局，每个卡片代表一个餐桌，卡片上显示餐桌名字、点餐状态，点击卡片可以查看该餐桌点菜的列表，有结账按钮，点击后就标记该订单的状态为已结账。

### 点餐页面

左侧分类导航列表，右侧多列（根据宽度调整列数）卡片布局，左侧分类列表只是快速定位到某个分类开始的地方，所有菜品都在右侧，左侧并不是类似 Tab 去切换右侧显示的东西的。右侧每个卡片代表一个菜单项，卡片上显示菜单项的名称、价格、描述、图片，还有一个数量编辑区，这个区域左右是增加和减少按钮，中间是当前数量的输入框，范围是正整数。

> 上面三个页面的多列卡片布局的列数量变化可以采用不一样的断点阈值，因为他们卡片内容复杂度不一样
